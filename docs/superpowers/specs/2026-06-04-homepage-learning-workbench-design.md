# 首页“工程师的学习工作台”设计规格

## 目标

将首页从分类目录升级为学习决策入口。用户进入页面后，应先理解自己适合哪条路径、当前下一步是什么，再浏览完整内容结构。

## 设计方向

采用已确认的“工程师的学习工作台”方向：

- 专业可信、清晰有序、实战务实。
- 保留现有行动蓝、提示琥珀、中性色和中文系统字体。
- 学习路径优先于内容目录。
- 使用结构化列表、分隔线和不对称布局，减少相同卡片堆叠。
- 不做培训机构招生页、默认文档模板、游戏化打卡应用或企业后台系统。

## 页面结构

### 1. 顶部导航

保留站点品牌和主要内容入口。导航重点是“学习首页、新手教程、技术专题、项目与场景、面试追问链”，并提供“继续学习”次级入口。

### 2. 首屏学习决策

左侧用一句明确标题解释站点价值：“找到下一步，把测试开发能力练出来”。正文说明知识、练习项目和面试表达之间的连接。

右侧展示学习路径摘要，包括当前路径、完成数量、当前建议步骤、预计时间和后续步骤。若用户没有本地进度，则展示新手基础路径的默认起点。

### 3. 学习方式选择

提供两个有明确主次的入口：

- 新手路线为主要入口，强调 7 天完成基础、接口测试练习和第一个可讲述的小项目。
- 面试冲刺为次级入口，强调项目、场景题和追问链。

两者不能做成视觉权重完全相同的卡片。

### 4. 四层能力地图

以“入门教学层、技术能力层、项目和场景层、面试表达层”组织十个内容类别。桌面端使用层级导航加结构化模块列表，移动端改为纵向分组。

模块展示标题和一句用途说明，不重复使用图标、徽章或装饰性卡片。

### 5. 进度反馈

进度只表达可理解的学习状态：当前路径、完成内容、下一步建议。避免使用没有学习意义的全站百分比、积分或奖励。

## 组件边界

- `HomeHero`：品牌标题、说明和主要行动。
- `LearningPathSummary`：读取本地进度，展示默认、进行中和完成状态。
- `LearningModeChoice`：展示新手与面试冲刺入口。
- `CapabilityMap`：根据四层信息架构渲染分类。
- `ProgressSummary`：展示可理解的完成结果，不承担主要首屏任务。

组件数据优先来自现有 `src/lib/home-page.ts`、`src/lib/site-config.ts` 和进度存储模块，避免在页面模板中重复维护分类数据。

## 数据流与状态

- 构建时数据：分类、四层结构、学习路径和入口链接。
- 客户端数据：本地学习进度、最近学习内容和完成数量。
- 无进度状态：默认推荐新手基础路径，并明确“从第 1 步开始”。
- 有进度状态：突出当前建议步骤和继续学习入口。
- 无法读取本地存储：页面保持可用，不显示错误弹窗，回退到默认路径。

## 可访问性

- 以 WCAG AA 为基线。
- 所有链接和按钮必须有清晰的键盘焦点状态。
- 颜色状态必须同时包含文字说明。
- 移动端触控目标不小于 44px。
- 动画支持 `prefers-reduced-motion`，并且内容不能依赖动画才可见。

## 响应式行为

- 桌面端首屏使用左右布局，路径摘要与品牌信息并列。
- 平板端允许首屏堆叠，但保持路径摘要在学习方式选择之前。
- 移动端导航精简，行动按钮可换行，能力地图按层级纵向展开。
- 标题使用流体字号，任何宽度下不能溢出容器。

## 测试与验证

- 单元测试验证首页数据仍包含新手与面试入口、四层结构和十个类别。
- 端到端测试验证主要链接使用 GitHub Pages 基础路径。
- 浏览器检查桌面、平板和移动端布局。
- 验证无本地进度、有本地进度和损坏本地存储三种状态。
- 检查键盘焦点、对比度、减少动态偏好和控制台错误。

## 不在本次范围

- 不重写 Starlight 内容页模板。
- 不新增账号、云端同步、积分或打卡功能。
- 不修改十个内容类别及新手教程的教学顺序。
