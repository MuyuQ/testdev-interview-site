## 你会学到什么

这节是整条路线的"地图"，帮你建立全局认知：

- 理解测试开发岗位到底做什么
- 掌握写测试需要的最小 Python 知识
- 写出第一个可运行的 Pytest 测试
- 理解 HTTP 和接口测试的基本概念
- 用代码完成一个登录接口测试小项目
- 学会用面试语言表达这个项目

这 6 项不是孤立的：Python 是地基，Pytest 是工具，HTTP/接口是测试对象，登录小项目是把前三样串起来的实战，面试表达是把实战翻译成语言。学完后，你会有一个可讲述的项目经历，能回答基础的面试追问。

## 为什么要学

很多功能测试或零基础的朋友想转测开，但常常：

- 不知道从哪里开始
- 学了很多零散知识，但不会组合成项目
- 写过一些代码，但面试时讲不清楚

为什么会卡在"讲不清楚"？因为面试不是考你背定义，而是追问"你这个东西覆盖了哪些场景""失败了你怎么定位"。没有真实做过项目，这些追问一问就空。

这条路线的设计思路是：**先学会，再冲刺**。不急着背诵面试答案，而是先完成一个真实的小项目，再学习怎么表达它。基础能力有了，表达才有东西可讲。

## 前置知识

你需要：

- 能安装软件（Python、VS Code）
- 能在命令行运行简单命令
- 有浏览器能访问网页
- 能中文阅读

不需要：

- 不需要先懂 Python
- 不需要先懂自动化框架
- 不需要先懂 HTTP

我会从零讲起，每节课只讲一个主概念，配一个最小例子和一个练习。

**如果你已经会 Python**：可以跳过 Day 3（Python 最小基础），直接从 Day 4（Pytest）开始，但建议还是扫一眼，确认自己熟悉函数、字典和 assert——它们会贯穿后面所有测试代码。

## 核心概念

这条路线用 **7 天** 覆盖入门基础，再用 **1 天** 练面试表达，共 8 个主题：

| 天数 | 主题 | 你会产出 |
| --- | --- | --- |
| Day 1 | 学习路线总览 | 写下 7 天目标 |
| Day 2 | 测试开发岗位理解 | 3 句话讲清测开职责 |
| Day 3 | Python 最小基础 | 读懂函数、列表、字典、assert |
| Day 4 | Pytest 第一个测试 | 运行一个通过和失败的测试 |
| Day 5 | HTTP 和接口基础 | 解释一次接口调用的过程 |
| Day 6 | 接口测试第一案 | 写一个最小接口测试用例 |
| Day 7 | 登录小项目 | 完成 3 条登录测试用例 |
| Day 8 | 面试表达 | 准备 2 分钟项目介绍 |

前 7 天是"打基础"，Day 8 属于后面的面试冲刺阶段，这里先列在一起让你看到完整闭环。

为什么是这个顺序？因为它遵循"工具 → 对象 → 实战"的递进：先有 Python 这个语言工具，再用 Pytest 把它变成测试工具，然后理解 HTTP 这个测试对象，最后把工具用在对象上做成项目。跳步会让你"看得懂代码但不知道为什么这么写"。

这也解释了为什么 Day 1 先给你一张地图：知道终点在哪，中途才不会因某个概念难就觉得自己走偏了。

路线的最终产出是：**一个可讲述的接口自动化小项目 + 一段面试表达**。

## 最小示例

这是路线的核心节奏，每一节都按它走：

```text
一个概念 → 一个例子 → 一个练习 → 一个检查 → 一个面试表达
```

比如学 Pytest 时：

- 概念：测试框架帮你自动发现和运行测试
- 例子：写一个 `test_add()` 函数，运行 `pytest`
- 练习：自己写一个测试 `test_multiply()`
- 检查：看到 `1 passed`
- 面试表达："我用 Pytest 写单元测试，运行 pytest 命令就能自动发现所有测试函数。"

注意节奏里的"面试表达"不是最后才做——每一节都顺手攒一句能说的话，到第 8 天就不用从零背。这也是为什么路线把"表达"拆进每一节，而不是堆到最后。

## 手把手练习

**练习：写下你的 7 天目标**

新建一个文本文件 `my-7-day-goal.txt`，写下：

1. 你每天能投入多少时间学习（建议至少 1-2 小时）
2. 你学完这条路线后想达到什么状态
3. 你最想解决的面试困难是什么

保存后，放在你每天能看到的地方。

**时间盒建议**：每节都标了预计时长（25–90 分钟）。练习时给自己设个闹钟，到时间就停，避免在一节里钻太深而拖慢整体节奏。卡住的地方先记下来，进入下一节后回头看，往往就通了。

## 检查标准

完成本节的标准：

- 你能说出这条路线从总览到面试表达的主题顺序（入门 7 天 + 冲刺 1 天）
- 你知道每天要做什么练习
- 你写下了自己的 7 天目标
- 你知道最终产出是什么

## 常见错误

**错误 1：想一次学完所有内容**

这条路线设计为每天一个主题。跳太快会消化不良。建议每天只学当前一节，完成练习再继续。

**错误 2：只看不练**

只看概念不写代码，面试时很难真的讲清楚。每节练习都要真的动手——哪怕只是把例子敲一遍，也比只读强。

**错误 3：急着背面试答案**

先完成小项目，再学表达。没有真实经历，背答案很容易被追问问穿。典型的追问是"你这个接口测试覆盖了哪些场景"，没做过项目的人答不上来。

**错误 4：在第一天反复打磨目标**

目标文件是"启动器"不是"合同"，写个大致方向就够了，别为了把计划写完美而迟迟不开始 Day 2。计划可以边走边调，动起来比写完美更重要。

## 面试怎么说

如果面试官问："你是怎么学习测试开发的？"，你可以回答：

"我先用一周时间完成了一条入门路线，从 Python 最小基础、Pytest 测试框架、HTTP 接口概念到写一个登录接口测试小项目。这个项目帮我建立了真实经验，之后我再进入面试冲刺内容，学习术语表达和追问链。"

这样回答展示了你的学习能力、实践经验和清晰的学习路径。比"我看了很多教程"有力得多，因为你能说出具体做了什么。
