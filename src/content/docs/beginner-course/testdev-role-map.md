## 你会学到什么

这节帮你建立岗位认知，后面学的每一项技能都能在这里找到位置：

- 理解测试开发岗位的职责边界
- 知道测开和功能测试、自动化测试、开发的关系
- 明确测开需要的能力
- 能用 3 句话向面试官解释测开角色

学完这节，你再看到"Python、Pytest、接口测试"这些词，会知道它们分别属于能力地图的哪一层，而不是一堆零散名词。

## 为什么要学

面试常问："你怎么理解测试开发？"如果你只能背定义，很容易被追问卡住。

典型追问："测开和自动化测试有什么区别？""那你和功能测试比强在哪？"——答不上来，多半是因为没建立岗位地图。

先搞清楚这个岗位到底做什么，后面学习 Python、Pytest、接口测试时，你才能理解每个技能在岗位中的位置：学 Python 是在补"编程能力层"，学接口测试是在补"测试基础层"加"工程化"的入口。

## 核心概念

### 测试开发 vs 功能测试

| 维度 | 功能测试 | 测试开发 |
| --- | --- | --- |
| 主要手段 | 手工操作、写用例文档 | 写代码、搭框架、做工具 |
| 效率来源 | 人力和经验 | 自动化脚本和平台 |
| 产出 | 测试用例、Bug 报告 | 自动化脚本、测试工具、质量报告 |
| 适用场景 | 新功能验证、用户体验测试 | 回归测试、接口测试、性能测试 |

一句话：功能测试侧重"验证产品对不对"，测试开发侧重"用代码让验证更快更稳"。

举个具体例子：每次发版要回归 100 个功能。功能测试需要人工逐个点一遍，可能花一整天；测开把核心用例写成脚本，pytest 几十秒跑完，还能接入 CI 每次提交自动跑。这就是"效率来源"差异的直观体现。

### 测试开发 vs 自动化测试

自动化测试是测开的一部分技能，但测开不止自动化：

- 自动化测试：用脚本跑测试（"把用例变成能自动执行的东西"）
- 测试开发：自动化 + 框架设计 + 工具开发 + 质量度量

"框架设计"具体指什么？比如把登录、鉴权、数据准备这些重复动作封装成公共函数或 fixture，让业务用例只写断言；"工具开发"比如做一个造数平台、一个结果对比工具。很多公司把"测开"和"自动化测试工程师"混叫，但岗位要求里常包含：框架设计、测试平台、CI 集成、报告设计。

### 测试开发 vs 开发

测开不是写业务代码的开发，但需要开发能力：

- 开发：写业务功能代码（用户能看到的功能）
- 测试开发：写测试代码（测试脚本、测试工具、Mock 服务）

测开需要懂代码，但目标不同：开发让产品功能跑起来，测开让产品质量可控。

举个代码层面的区别：开发写的是 `def create_order(user, item): ...` 这种业务函数；测开写的是 `def test_create_order(): ... assert ...` 这种验证函数。同样是 Python，关注的"对象"完全不同。

### 岗位能力地图

测开的能力可以分为 4 层，越往下越基础：

```text
第一层：测试基础
  - 测试设计方法（等价类、边界值、场景法）
  - 用例编写
  - Bug 管理（提交、跟踪、回归）

第二层：编程能力
  - Python/Java
  - 测试框架（Pytest/TestNG）
  - 接口调用（requests 等）

第三层：工程化能力
  - 自动化框架设计
  - CI/CD 集成（提交即跑）
  - 测试平台开发（Web 化管理用例）

第四层：专项能力
  - 性能测试（压测、瓶颈定位）
  - 安全测试（越权、注入）
  - 测试数据管理（造数、脱敏）
```

不同公司对各层权重不同：业务稳定的中台团队最看重第二、三层；强监管行业（金融、医疗）会强调第四层的安全与数据合规。

这条新手路线重点覆盖第一层（测试设计入门）和第二层（Python + Pytest + 接口），帮你建立最核心的"测试基础 + 编程能力"。第三、四层是后续进阶方向，路线里会点到但不展开。

## 最小示例

用招聘 JD 来理解岗位要求，把关键词对到能力地图：

```text
某公司测开 JD 关键词：
- Python/Java            → 第二层 编程能力
- Pytest/TestNG/Junit    → 第二层 测试框架
- 接口自动化             → 第二层 接口调用 + 第一层 用例设计
- CI/CD                  → 第三层 工程化
- 测试框架维护           → 第三层 框架设计
```

如果你只会手工测试（第一层部分），后面 4 项要求很难满足。这条路线帮你建立前两项（Python + Pytest）和接口基础，后续你可以继续扩展 CI/CD、框架设计，补齐第三层。

**练习：用 3 句话解释测试开发**

写在你的学习笔记里，并标注每句话对应能力地图的哪一层：

1. 第一句：测开是做什么的？（侧重工程能力）→ 对应第几层？
2. 第二句：测开和功能测试的区别？（效率和产出）→ 对应第几层？
3. 第三句：测开的核心产出是什么？（脚本、框架、工具）→ 对应第几层？

## 常见错误

**错误 1：把测开等同于自动化测试**

测开不止写脚本，还包括框架设计、工具开发、CI 集成。只学脚本不够。面试追问"你怎么设计框架"时，只答"我会写脚本"会显得层次不够。

**错误 2：认为测开要和开发一样强**

测开需要代码能力，但目标是测试质量，不是写业务功能。代码深度可以比开发浅，但要懂测试应用——比如知道怎么用 fixture 管理测试数据，比会写复杂业务算法更相关。

**错误 3：忽视测试基础**

只学代码不学测试设计，写出的脚本可能覆盖面很差。测试用例设计（等价类、边界值）仍然是基础，否则自动化只是"把错误的检查跑得更快"。

## 面试怎么说

如果面试官问："你怎么理解测试开发？"，可以这样回答：

"测试开发是用工程能力提升测试效率和质量的岗位。和功能测试相比，测开不只是验证产品功能，还要把验证过程自动化、可复用。核心产出是自动化脚本、测试框架和质量工具，目标是让回归测试、接口测试能高效稳定执行。"

这个回答展示了你对岗位的理解、产出目标和效率价值。

**追问应对**：如果接着被问"那自动化测试和测开的区别？"，补一句："自动化测试是测开的核心手段之一，但测开还包含框架设计和平台开发，不只是写跑用例的脚本。"——这句正好对应能力地图的第三层。
