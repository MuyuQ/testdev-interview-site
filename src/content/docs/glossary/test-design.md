## 一句话定义

测试设计是确定测试目标、选择合适的测试方法、设计高质量测试用例的系统性过程，是连接测试需求与测试执行的关键桥梁。

## 为什么测试开发要关心它

测试设计直接决定了测试的有效性和效率。好的测试设计能够：
- **用最少的用例覆盖最多的风险**，避免冗余测试浪费资源
- **发现隐蔽缺陷**，边界值和异常场景往往是 Bug 的重灾区
- **提升面试竞争力**，大厂必问测试设计方法，体现基本功
- **指导自动化测试策略**，知道测什么才能更好地设计自动化框架

## 它在真实工作流中的位置

```
需求分析 → 测试设计 → 用例编写 → 用例评审 → 测试执行 → 缺陷报告
              ↑
          （核心环节）
```

测试设计处于需求分析和用例编写之间，是将业务需求转化为可执行测试用例的关键环节。测试开发工程师在这个阶段需要：
1. 分析需求的输入输出、约束条件
2. 选择合适的测试设计方法（等价类、边界值、场景法等）
3. 产出结构化的测试用例

## 一个最小例子

### 场景：用户年龄输入框（限制 18-65 岁）

```javascript
// 测试设计方法应用示例

// 1. 等价类划分
// 有效等价类：18-65 岁（选 30 作为代表）
// 无效等价类：<18 岁、>65 岁、非数字、空值

const equivalenceClassTests = [
  { input: 30, expected: 'valid', desc: '有效等价类代表值' },
  { input: 17, expected: 'invalid', desc: '无效等价类-小于下界' },
  { input: 66, expected: 'invalid', desc: '无效等价类-大于上界' },
  { input: 'abc', expected: 'invalid', desc: '无效等价类-非数字' },
];

// 2. 边界值分析
// 边界点：18、65
// 边界±1：17、19、64、66
// 补充：边界点外再取一点：0、100

const boundaryTests = [
  { input: 17, expected: 'invalid', desc: '下边界-1' },
  { input: 18, expected: 'valid', desc: '下边界点' },
  { input: 19, expected: 'valid', desc: '下边界+1' },
  { input: 64, expected: 'valid', desc: '上边界-1' },
  { input: 65, expected: 'valid', desc: '上边界点' },
  { input: 66, expected: 'invalid', desc: '上边界+1' },
];

// 3. 场景法
// 基本流：正常输入年龄 → 提交成功
// 备选流1：输入无效年龄 → 提示错误
// 备选流2：未输入直接提交 → 提示必填
// 备选流3：连续输入错误 → 账户锁定

const scenarioTests = [
  {
    name: '正常注册流程',
    steps: ['进入注册页', '输入有效年龄30', '点击提交'],
    expected: '注册成功'
  },
  {
    name: '异常流程-年龄超限',
    steps: ['进入注册页', '输入年龄10', '点击提交'],
    expected: '提示年龄不符合要求'
  },
];
```

## 面试怎么说

"测试设计是测试开发的核心技能之一。我主要掌握三种经典方法：

**等价类划分**的核心思想是将输入域划分为若干等价类，每个等价类中的数据对于揭露错误是等效的。比如一个年龄输入 18-65，有效等价类选一个代表值就行，无效等价类要分别考虑低于下界和高于上界。

**边界值分析**是我最常用的方法，因为大量缺陷发生在边界附近。对于闭区间 [a, b]，我会测试 a-1、a、a+1、b-1、b、b+1 这些点。

**场景法**更贴近用户视角，我会从基本流出发，逐步叠加备选流来设计场景。比如登录功能，正常登录是基本流，密码错误、账号不存在、连续失败锁定都是备选流。

在项目中，我通常会组合使用这些方法，先用等价类划分减少冗余，再用边界值分析补充边界点，最后用场景法覆盖业务流程。"

## 易错点

1. **等价类划分遗漏无效等价类**
   只考虑有效输入，忘记测试无效输入（如非数字、空值、特殊字符），导致缺陷遗漏。

2. **边界值分析不完整**
   只测边界点本身，忘记边界±1；或者混淆开闭区间，导致边界判断错误。

3. **场景法只关注正常流程**
   设计测试时过度关注"快乐路径"，忽视异常场景和错误处理，而这恰恰是 Bug 高发区。

4. **盲目追求数量**
   认为测试用例越多越好，实际上冗余用例不仅浪费测试时间，还稀释了真正有价值的测试。

5. **方法选择僵化**
   不同场景适合不同方法，比如逻辑复杂的业务用场景法，输入输出明确的功能用等价类和边界值。

## 容易混淆的概念

| 概念 | 定义 | 关键区别 |
|------|------|----------|
| 等价类划分 | 将输入域划分为若干等价类，每类选代表值 | 关注**分类**，减少冗余 |
| 边界值分析 | 在边界附近选取测试值 | 关注**边界**，发现边界缺陷 |
| 场景法 | 从用户视角模拟使用场景 | 关注**流程**，贴近业务 |

**常见混淆：边界值 vs 等价类**

等价类是"分类"思维，把输入分成几块，每块选一个代表；边界值是"边界"思维，专门在边界附近挖 Bug。两者是互补关系，不是替代关系。

**常见混淆：黑盒测试方法 vs 白盒测试方法**

等价类、边界值、场景法都是黑盒测试方法，不需要了解内部实现；语句覆盖、分支覆盖、路径覆盖是白盒测试方法，需要看到代码逻辑。

   - A. 1, 6, 12
   - B. 0, 1, 12, 13
   - C. 0, 1, 2, 11, 12, 13
   - D. 1, 12

   <details>
   <summary>点击查看答案</summary>
   答案：C。边界值分析需要覆盖边界点、边界点-1、边界点+1。月份范围[1,12]，完整测试应包括：0(下界-1)、1(下界)、2(下界+1)、11(上界-1)、12(上界)、13(上界+1)。
   </details>

2. **思考题**：等价类划分和边界值分析通常如何配合使用？请举例说明。

   <details>
   <summary>点击查看答案</summary>
   先用等价类划分确定有效和无效等价类，然后在每个等价类的边界处应用边界值分析。例如成绩输入0-100分：先用等价类划分确定有效类(0-100)和无效类(<0, >100)，再对边界0和100分别测试-1、0、1和99、100、101。
   </details>
