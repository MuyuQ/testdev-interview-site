## 模块定位

练手模板模块解决的核心问题是：**如何将零散的技术知识点转化为可展示的项目产物和面试素材**。

很多学习者的痛点是：学完了 Pytest、Requests、Selenium 等技术，但在面试时拿不出像样的项目作品，或者项目经验说不清楚。这个模块提供标准化的项目模板和故事框架，帮助学习者：

- 快速搭建专业级的项目骨架
- 产出可以直接放在 GitHub 上的代码仓库
- 掌握面试时描述项目经验的标准话术
- 避免从零开始摸索项目结构

## 适合谁

### 初学者

如果你刚学完基础语法和测试框架，用这个模块：
1. 按模板搭建第一个完整项目，建立正确的项目结构意识
2. 学习配置管理、代码组织等"课本上没有"的工程实践
3. 获得可以写入简历的项目经验雏形

### 冲刺面试者

如果你在准备面试，用这个模块：
1. 重点学习每个模板的「面试怎么说」部分
2. 用模板搭建 2-3 个项目，覆盖接口自动化、Mock 服务等方向
3. 结合项目故事模板，打磨自己的项目叙述能力

### 项目包装者

如果你有零散的练习代码，需要整理成正式项目：
1. 参考模板的目录结构，重组现有代码
2. 补充 README、配置文件、报告生成等缺失部分
3. 按验收清单检查项目完整性

### 进阶测试开发

如果你已经有一定经验，用这个模块：
1. 对比自己的项目实践与模板的差异，查漏补缺
2. 将模板作为团队规范的基础，推广到项目中
3. 扩展模板，形成自己的脚手架工具

### 项目实战

完成基础模板后，建议进行以下实践：

1. **接口自动化实战**：选择一个公开 API（如 GitHub API），搭建完整的测试项目
2. **Mock 服务进阶**：为实际项目搭建 Mock 服务，模拟第三方接口
3. **项目整合**：将 Mock 服务集成到接口自动化项目中，实现完全隔离测试

## 最小完成标准

要算是「掌握练手模板模块」，至少完成以下内容：

### 基础标准（必做）

- [ ] 完成 API 自动化模板学习，搭建出符合目录结构规范的项目
- [ ] 至少编写 10 个接口测试用例，使用参数化
- [ ] 成功生成 Allure 测试报告
- [ ] 完成 Mock 服务模板学习，能独立搭建 Mock 服务
- [ ] 至少模拟 3 种异常场景（超时、错误码、网络异常）

### 进阶标准（推荐）

- [ ] 项目 README 包含完整的运行说明和架构图
- [ ] 将练习项目上传到 GitHub，有清晰的 commit 记录
- [ ] 用项目故事模板准备 2 个可说的项目案例
- [ ] 能流畅回答「项目怎么组织的」「遇到过什么难点」等面试问题

## 常见误区

### 误区一：只看不练

很多学习者把模板当成文档「读完就算」，没有实际动手搭建项目。

**正确做法**：每个模板都有「手把手练习」部分，必须实际敲代码、建目录、运行测试。只有产出真实的项目骨架，才能真正掌握。

### 误区二：复制粘贴了事

直接复制模板代码，不理解每个目录和文件的作用。

**正确做法**：
1. 先理解模板设计的「为什么」—— 为什么配置要单独目录？为什么 fixture 要分文件？
2. 尝试修改模板，比如换一个 API 域名、增加一个测试模块
3. 能解释每个设计决策的原因

### 误区三：忽视面试准备

有了项目代码，但面试时说不清楚项目亮点和技术难点。

**正确做法**：
1. 每完成一个模板，就对照「面试怎么说」部分进行自我演练
2. 用项目故事模板整理项目叙述逻辑
3. 找同学或朋友模拟面试，练习项目介绍

### 误区四：贪多求全

想同时学接口自动化、UI 自动化、性能测试等所有方向。

**正确做法**：
1. 先精通一个方向（推荐接口自动化）
2. 掌握核心方法论后，再横向扩展
3. 质量 > 数量，一个完整的项目胜过十个半成品

### 误区五：忽视代码质量

项目结构是对的，但代码缺乏注释、命名不规范、没有错误处理。

**正确做法**：
1. 参考模板中的代码风格
2. 使用 Lint 工具（如 flake8、pylint）检查代码质量
3. 每个测试用例有清晰的文档字符串
4. 代码提交前自查：别人能看懂我写的代码吗？
