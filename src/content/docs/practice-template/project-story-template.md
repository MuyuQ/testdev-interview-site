## 模板目标

项目故事模板帮助你把测试工作包装成有深度的面试表达。很多人面试时讲项目像流水账："我做了一个电商项目，写了接口测试，用 Pytest 框架"——这种回答没有亮点，无法体现你的能力。

这个模板教你用结构化的方式讲述项目：

- 让面试官快速理解你的贡献和价值
- 展示技术深度而非只列举工具名称
- 提前准备好追问应对，不被打乱节奏

## 适用场景

- 面试时回答"介绍一下你的项目经历"
- 简历项目描述的撰写
- 自我介绍中的项目概述
- 年终汇报或晋升答辩的项目总结

## 使用前提

使用这个模板前，你需要：

- 有至少一个完整的测试项目经历（真实参与，不是只看文档）
- 能说出项目的技术栈和测试策略
- 能回忆至少一个技术难点和解决过程
- 有一些可量化的成果（用例数量、覆盖率、发现缺陷数等）

如果没有项目经历，建议先完成 [新手教程](/testdev-interview-site/beginner-course/) 和 [API 自动化模板](/testdev-interview-site/practice-template/api-automation-template/)，积累一个可讲的项目。

## 最终产物

完成这个模板后，你将得到：

1. **2分钟项目概述**：一段完整的项目介绍，控制在2-3分钟
2. **追问应对清单**：至少5个可能的追问点和回答要点
3. **量化成果数据**：至少3个可说的数字（用例数、覆盖率、缺陷数等）
4. **技术难点故事**：一个完整的技术难点解决过程

## 内容结构

项目故事采用五步闭环结构：

```text
背景 → 职责 → 做法 → 结果 → 复盘
```

### 第一步：背景（30秒）

讲清楚项目是什么、解决什么业务问题、有什么价值。

```text
【模板】
这个项目是[项目类型]，服务于[用户群体]，核心目标是[业务目标]。
项目的技术架构是[架构类型]，日均[数据量]，峰值[并发量]。

【示例】
这个项目是一个电商平台，服务于C端购物用户，日均订单50万。
技术架构是微服务，核心链路包括浏览、下单、支付、发货四个环节。
```

**要点**：

- 不要只说"我做了一个电商项目"，要说明规模和特点
- 数据量、并发量能让面试官感知项目复杂度
- 如果没有真实数据，可以用相对描述：中等规模、用户量较大

### 第二步：职责（20秒）

说明你在项目中负责什么，不负责什么，划定边界。

```text
【模板】
我在项目中负责[核心职责]，具体包括[3-4项具体工作]。
我不负责[非职责范围]，这部分由[其他角色]负责。

【示例】
我在项目中负责测试策略设计和自动化框架搭建。
具体包括：接口自动化框架开发、核心用例编写、支付和库存专项测试、
质量体系建设。不负责手工测试执行，这部分由功能测试团队负责。
```

**要点**：

- 职责要具体，不要只说"负责测试"
- 划定边界很重要，避免被追问超出职责范围的问题
- 体现测试开发的定位：策略、框架、专项、体系建设

### 第三步：做法（60秒）

这是核心部分，展示技术深度。不要列举工具，要讲设计思路。

```text
【模板】
我的做法分为三个部分：

第一是[第一部分工作]。我[具体做法]，因为[设计理由]。
遇到[问题]，通过[解决方法]解决。

第二是[第二部分工作]。我[具体做法]，选择[技术选型]是因为[理由]。

第三是[第三部分工作]。我[具体做法]，重点是[关键点]。

【示例】
我的做法分为三个部分：

第一是自动化框架搭建。我设计了三层架构：配置层用 YAML 管理环境配置，
封装层统一处理请求和断言，测试层按业务模块划分。这样设计是为了
解耦配置和代码，方便维护和多环境切换。

第二是支付专项测试。支付回调涉及幂等性，我设计了三层保障机制：
数据库唯一索引、Redis 分布式锁、状态校验。测试时模拟了网络抖动、
重复回调等异常场景，验证不会重复发货。

第三是测试数据管理。我开发了数据工厂工具，可以一键构造各种状态的
订单数据，比如已支付待发货、已取消等。这样测试不同场景不需要
手动准备数据，效率提升很多。
```

**要点**：

- 不要说"我用 Pytest 写测试"，要说"我设计了三层架构"
- 每个做法都要有设计理由，体现思考而非执行
- 提一个遇到的问题和解决过程，展示解决问题的能力
- 做法数量控制在2-3个，每个都要能展开追问

### 第四步：结果（30秒）

量化成果，用数字说话。

```text
【模板】
通过这些工作，项目取得了[量化成果]：
- [成果1数据]
- [成果2数据]
- [成果3数据]

【示例】
通过这些工作，项目取得了明显改善：
- 接口自动化覆盖率达到85%，每次代码提交自动执行
- 支付相关问题下降80%，上线后核心链路无故障
- 测试数据准备时间从30分钟缩短到5分钟
```

**要点**：

- 成果要有数字，不要只说"效果很好"
- 数字要合理，不要夸大或虚假
- 如果没有精确数字，可以用相对描述：大幅提升、明显改善

### 第五步：复盘（20秒）

体现成长思维和总结能力。

```text
【模板】
这个项目让我对[领域]有了深入理解，特别是[具体点]。
如果重来一次，我会[改进点]。

【示例】
这个项目让我对分布式系统的测试有了深入理解，特别是幂等性、
并发控制、数据一致性这些难点。如果重来一次，我会更早引入
契约测试，避免服务间接口变更导致的测试不稳定。
```

**要点**：

- 复盘要具体，不要只说"学到很多"
- 改进点体现思考能力，但不能太多以免被追问

## 分步完成方式

### 步骤一：准备项目素材

填写以下表格，梳理项目信息：

| 项目要素 | 你的答案                           |
| -------- | ---------------------------------- |
| 项目类型 | 如：电商平台、支付系统、管理后台   |
| 用户群体 | 如：C端用户、B端商家、内部运营     |
| 业务目标 | 如：提升交易转化、保障支付安全     |
| 技术架构 | 如：微服务、单体应用、前后端分离   |
| 数据规模 | 如：日均50万订单、峰值3000QPS      |
| 你的职责 | 如：自动化框架、专项测试、质量体系 |
| 具体做法 | 如：三层架构设计、幂等性测试方案   |
| 遇到问题 | 如：支付回调丢失、库存超卖         |
| 解决方法 | 如：增加消息队列缓冲、引入分布式锁 |
| 量化成果 | 如：覆盖率85%、缺陷下降80%         |
| 技术收获 | 如：理解分布式系统测试难点         |
| 可改进点 | 如：更早引入契约测试               |

### 步骤二：编写项目概述

根据素材，按五步结构写一个2-3分钟的概述。用文字写出来，计时朗读检查时长。

### 步骤三：准备追问应对

列出至少5个可能的追问点和回答要点：

| 可能追问               | 回答要点                                        |
| ---------------------- | ----------------------------------------------- |
| 为什么选择 Pytest？    | 对比其他框架的优势，如参数化、Fixture、插件生态 |
| 幂等性怎么保证？       | 三层机制：唯一索引、分布式锁、状态校验          |
| 并发测试怎么设计？     | 压测工具、验证库存扣减准确性、检查超卖          |
| 数据工厂怎么实现的？   | 封装接口调用、预设数据模板、一键构造            |
| 测试覆盖率怎么统计的？ | JaCoCo 代码覆盖、接口覆盖统计、定期 review      |

### 步骤四：练习表达

录音练习，检查：

- 时长是否控制在2-3分钟
- 是否有工具列举而非设计思路
- 是否有"我们"代替"我"（可能被追问你的具体贡献）
- 是否有无法追问的点（流水账、泛泛而谈）

### 步骤五：模拟追问

让朋友或同事模拟追问，检查回答是否有深度，是否会被追问打断节奏。

### 练习达标线（可操作自检）

- 用手机录音朗读"项目概述"，计时落在 **2 分 00 秒 ~ 2 分 40 秒** 之间；太短没信息量，太长易被叫停
- 回放时数"我们"出现几次——凡能落到你个人动作的，改成"我"（"我们搭了框架"→"我设计了三层架构"）
- 回放时标记所有"工具名罗列"处（如"用了 Pytest、Jenkins"），补一句"为什么选它"
- 挑选 1 个技术难点，确保能讲清"问题→分析→尝试→最终方案→验证"五环

完成模板后，检查以下要点：

- [ ] 项目概述时长控制在2-3分钟

- [ ] 职责部分划定边界，说明负责和不负责什么

- [ ] 练习录音听起来自然，不是背诵感

## 完整故事示例（可直接套改）

> **示例数字请替换成你的真实数据。** 下面的人物、项目和数字都是演示用的虚构设定，重点学的是结构和表达方式。面试官一定会追问数字的统计口径，编造的数字答不上"怎么统计的"就穿帮了。

设定：3 年经验测试开发，在一家本地生活平台负责商家结算系统的测试。

### 两分钟项目概述（第一人称完整版）

> 我在上一家公司负责商家结算系统的测试。这个系统服务于平台上的几十万商家，每天要出大概 8 万笔结算单，月底峰值 QPS 到过 1200，属于"算错一分钱商家就来投诉"的钱类系统。
>
> 我在项目里负责测试策略设计和自动化框架搭建，具体做了三块：接口自动化框架、结算金额准确性专项、第三方支付渠道的 Mock 体系。手工回归执行不归我管，由功能测试同学负责。
>
> 具体做法上，第一是搭了三层架构的接口自动化框架：配置层用 YAML 管理多环境，封装层统一处理请求、认证和日志，测试层按业务模块划分。选 Pytest 是因为 fixture 能把登录、造数据、清理这些前置收敛到一处，用例里只剩业务动作。第二是结算金额专项，我重点测分摊和四舍五入：优惠券跨多个商品怎么分摊、0 元单、负向优惠这些边界，每条用例都下数据库逐单核对金额，不只看接口返回。第三是给第三方支付渠道建了 Mock，模拟渠道超时和重复回调，验证结算单不会被重复推进。
>
> 结果上，接口自动化用例积累到 320 条，核心接口覆盖率 78%，回归从 2 天人工压到 40 分钟自动跑完；上线后金额类缺陷从月均 9 个降到 2 个。
>
> 复盘下来，这个项目让我对钱类系统的测试有了体系化的理解，特别是幂等和分摊规则。如果重来一次，我会更早引入契约测试——当时渠道接口改过一次字段，我们的 Mock 没同步，空跑了两天假绿。

这段概述的时长约 2 分 10 秒（按正常语速朗读），五步比例大致是背景 20 秒、职责 15 秒、做法 60 秒、结果 15 秒、复盘 20 秒，和模板约定一致。

### 5 个高频追问的应答要点

| 追问                               | 应答要点                                                                                                               |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 78% 覆盖率怎么统计的？             | 按接口清单算：核心接口 180 个，自动化覆盖 141 个。剩下的低频运营接口投入产出比低，只做冒烟，所以敢报一个不满 100% 的数 |
| 分摊和四舍五入怎么设计用例？       | 边界值法：尾差一分钱的分摊场景、多张券叠加、整单退款后再部分退款；断言落到数据库逐单核对                               |
| 渠道 Mock 和真实渠道有差异怎么办？ | Mock 只负责流程隔离和异常模拟；金额规则以渠道沙箱联调为准，上线前有一轮真实沙箱回归                                    |
| 40 分钟怎么算的？                  | CI 全量 320 条用例的耗时加报告生成，Allure 里每次构建有 duration 记录，不是估的                                        |
| 月均 9 个降到 2 个怎么界定的？     | 按缺陷标签里的"金额计算"类目统计上线后缺陷，取上线后连续 3 个月对比上线前 3 个月                                       |

### 套改顺序：把示例换成你的故事

1. **先换事实**：项目类型、职责边界、技术难点换成你自己的，五步结构和各步时长比例不要动。
2. **再换数字**：每个数字都找真实来源（平台报表、Allure 统计、缺陷标签），找不到来源的改成相对描述，比如"约八成""明显下降"，比编一个精确数安全。
3. **再练追问**：对"做法"部分出现的每个技术名词，准备一句"为什么选它、对比过什么方案"。
4. **最后录音计时**：朗读落在 2 分 00 秒到 2 分 40 秒之间；超时优先砍背景和复盘，不要砍做法。

## 使用避坑

1. **口述数字和简历对不上**：面试官手里拿着你的简历，你口述覆盖率 78%、简历写 90%，交叉验证当场穿帮，比没有数字更糟。改一处就同步另一处，两者必须同源。
2. **全程"我们"，没有"我"**：团队话术显得你参与了，但面试官无法判断你的贡献，一定会追问"这里你具体做了什么"。凡是落到你个人动作的，都用"我 + 具体动词"。
3. **背稿痕迹重，一追问就断**：概述背得滚瓜烂熟，追问第一个"为什么"就卡壳，背稿感反而减分。概述只记五步骨架和三个数字，细节靠追问现场展开；至少找人模拟追问两轮。
4. **复盘假大空或自曝过度**：复盘只说"学到很多"等于没说；反过来把致命失误讲成亮点（"我把配置提交错了导致返工三天"）也不行。选一个"非致命、已有改进动作"的点，一句带过。
