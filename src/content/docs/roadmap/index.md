## 模块定位

学习路线模块解决的是「知道学什么，但不知道怎么学」的问题。很多测试开发学习者收集了大量资料，却缺乏系统的学习路径规划，导致学习碎片化、效率低、难以形成完整的知识体系。本模块提供**时间盒学习路线**，用明确的任务清单和产出要求，帮助你在有限时间内高效达成学习目标。

核心特点：
- **时间约束**：每条路线都有明确的时间范围（3天、7天等），避免无限拖延
- **任务驱动**：每天有具体的任务清单，不是模糊的「去学习」指令
- **产出可见**：强调产出物，让你能看见自己的进步和成果
- **验收标准**：每阶段都有验收清单，确保学习质量

## 适合谁

### 零基础入门者

如果你刚接触测试开发领域，建议先完成技术模块和词汇表模块的基础内容，再进入学习路线。本模块的路线都假设你有一定基础，不适合完全零基础的学习者。

**建议路径**：先浏览 `/tech` 和 `/glossary` 的基础词条，建立初步认知后，再选择面试冲刺路线。

### 冲刺面试者

即将面临面试（1-2周内），需要快速梳理知识体系、打磨项目表达。本模块提供了两条面试冲刺路线：

- **[3天面试速记](./3-day-interview-map)**：临门一脚的冲刺路线，唤醒已有记忆，适合基础扎实但需要快速回顾的学习者
- **[7天面试计划](./7-day-interview-plan)**：高密度面试冲刺路线，每天4个核心任务，产出面试作品集

### 项目包装者

有项目经验但不知道如何有效表达，需要将项目经历转化为结构化的面试素材。

- **[自我介绍模板](./self-introduction-template)**：掌握面试自我介绍的标准结构，用四段式表达展示核心竞争力
- 结合7天面试计划的Day 1-2项目经历打磨任务

### 进阶测试开发

已有一定工作经验，需要系统梳理知识体系、准备技术晋升答辩。

- 可以选择面试路线作为知识复盘框架
- 重点关注技术亮点挖掘和量化成果提炼部分

## 推荐学习顺序

以下是本模块的核心入口，建议按以下顺序学习：

1. **[自我介绍模板](./self-introduction-template)** - 面试第一关，掌握四段式结构（1-3分钟版本）
2. **[7天面试计划](./7-day-interview-plan)** - 面试系统准备，产出可见的面试作品集
3. **[3天面试速记](./3-day-interview-map)** - 临门一脚冲刺，唤醒已有记忆
4. `/tech/api-testing` - API测试核心知识（技术模块）
5. `/tech/test-automation` - 自动化测试框架（技术模块）
6. `/glossary` - 核心词条速查（词汇表模块）
7. `/project` - 完整项目演练（实战模块）
8. `/tech/performance-testing` - 性能测试要点（技术模块）
9. `/tech/cicd` - CI/CD与工具链（技术模块）

**时间建议**：
- 面试在1周内 → 直接进入3天面试速记
- 面试在2周内 → 选择7天面试计划
- 面试时间充裕 → 先学技术模块，再用学习路线复盘

## 内容分组

### 基础准备

- 自我介绍模板：建立结构化表达的基础能力
- 知识体系梳理：对照简历技术栈，建立知识索引

### 面试冲刺

- 3天面试速记：高强度冲刺，适合临门一脚
- 7天面试计划：系统准备，产出面试作品集

### 项目表达

- STAR法则拆解：将项目经历转化为结构化故事
- 量化成果提炼：用数据证明你的贡献和能力
- 技术亮点挖掘：识别项目中的技术难点和创新点

### 模拟追问

- 追问类型学习：原理追问、对比追问、场景追问、深挖追问
- 回答策略训练：结构化思路、分步骤分析、诚实应对
- 压力测试：面对不熟悉问题的应对方式

### 综合演练

- 模拟面试全流程
- 自我评价与复盘
- 面试应急笔记制作

## 最小完成标准

完成本模块的学习，需要达到以下最小标准：

### 面试准备最小标准

- [ ] 完成自我介绍模板的学习，有1-3分钟版本定稿
- [ ] 至少有3个项目的STAR结构描述文档
- [ ] 每个项目至少有3个量化成果
- [ ] 能口述任一项目不超过2分钟
- [ ] 面试问题清单覆盖所有核心模块（至少50题）
- [ ] 完成至少1次完整的模拟面试

### 知识复盘最小标准

- [ ] 核心概念速查表（不超过2页A4）
- [ ] 知识体系思维导图
- [ ] 能在不看资料的情况下清晰解释测试类型和层级的区别
- [ ] 能说出接口测试的5个核心概念及其应用场景

### 产出物清单

| 产出物 | 用途 | 建议数量 |
|--------|------|----------|
| 自我介绍定稿 | 面试开场 | 1-3分钟版本各一份 |
| 项目STAR故事卡 | 项目讲述 | 每个项目2-3个故事 |
| 量化成果清单 | 简历和面试 | 每个项目至少3个 |
| 技术亮点卡片 | 追问应对 | 每个项目至少2个 |
| 面试问题清单 | 复习索引 | 至少50题 |
| 模拟面试记录 | 改进依据 | 至少1次完整记录 |

## 常见误区

### 误区1：把学习路线当成从零学习的教程

学习路线是**冲刺复习工具**，不是从零学习的教程。所有路线都假设你有一定基础，如果你是零基础，建议先完成技术模块的基础学习。

**正确做法**：先建立基础认知，再用学习路线进行系统梳理和面试冲刺。

### 误区2：只看不练，没有产出

学习路线的核心是「产出可见」，每个任务都有明确的产出要求。如果只阅读不实践，就无法达到学习效果。

**正确做法**：严格按照任务清单产出文档、卡片、清单等可见成果。

### 误区3：期望押中面试题

学习路线强调的是通用能力和表达结构，不是面试题背诵。面试题目千变万化，但能力框架是可以复用的。

**正确做法**：掌握STAR结构、回答策略等框架方法，结合自己的真实项目经验填充内容。

### 误区4：死磕卡点不调整

遇到卡点时（知识点记不起来、项目讲不清楚），有些人会死磕不放，导致整体进度延误。

**正确做法**：参考「遇到卡点怎么调整」部分，灵活调整计划，优先保证核心产出。

### 误区5：自我介绍复述简历全文

自我介绍不是简历的全文朗读，而是简历的「预告片」。好的自我介绍让面试官产生兴趣，主动追问你想让他问的内容。

**正确做法**：掌握四段式结构，突出核心竞争力，控制在1-3分钟内。

## 下一步

完成本模块的学习后，根据你的目标选择下一步路径：

### 面试通过后

- 进入职业发展规划（规划下一阶段的学习目标）
- 深入技术模块（选择一个技术栈深入学习）
- 持续产出（将代码示例整理到GitHub，形成作品集）

### 面试未通过

- 根据面试反馈，回到对应的知识模块深入学习
- 补充项目经验，积累更多可讲述的案例
- 重新梳理自我介绍和项目表达

### 需要持续提升

| 薄弱环节 | 推荐下一步 |
|----------|------------|
| 自动化基础薄弱 | `/tech/test-automation` |
| API测试不够深入 | `/tech/api-testing` |
| 编程能力不足 | `/tech/python` 或 `/tech/java` |
| 项目经验不足 | `/project` 完整项目演练 |
| 面试技巧欠缺 | 重新演练模拟面试 |

### 每周保持

- 每周复盘：回顾面试问题清单，更新答案
- 每周练习：至少完成2道编程题
- 每周产出：整理新的代码片段或技术笔记

> **核心原则**：学习路线是框架，不是答案。掌握结构和方法，用自己的真实经验填充内容，才能形成属于你的面试竞争力。
