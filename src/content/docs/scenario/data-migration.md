## 一、场景题原问

面试官可能会这样问：

> "公司需要从旧系统迁移数据到新系统，数据量约500万条，涉及用户、订单、支付三个核心业务模块。作为测试负责人，你如何设计迁移测试方案？"

这个问题考察的是：迁移策略设计能力、风险识别能力、测试完整性思维。

## 二、确认边界

在接到数据迁移任务时，首先需要确认以下边界：

### 2.1 数据范围边界
- 迁移哪些业务模块的数据？用户、订单、支付是否全部迁移？
- 是否存在历史数据归档需求？如只迁移近3年数据
- 是否有数据过滤条件？如只迁移活跃用户数据

### 2.2 时间边界
- 迁移窗口期是多长？是否允许停机？
- 迁移截止时间是什么时候？
- 是否需要分批迁移？每批时间间隔？

### 2.3 系统边界
- 新旧系统是否并行运行？并行期多长？
- 迁移期间新数据如何处理？双写还是增量同步？
- 第三方系统是否受影响？接口是否需要适配？

### 2.4 质量边界
- 允许的数据差异率是多少？
- 是否允许数据格式转换？转换规则是什么？
- 迁移失败的数据如何处理？

## 三、风险分析

数据迁移涉及的主要风险：

### 3.1 数据完整性风险
- 数据丢失：迁移过程中部分记录未成功写入
- 数据重复：同一条记录被多次迁移
- 数据截断：字段值超长或格式不匹配导致截断

### 3.2 数据一致性风险
- 关联数据断裂：外键关系未正确维护
- 状态不一致：关联表状态更新不同步
- 时间戳问题：迁移时间与原时间差异导致业务逻辑异常

### 3.3 业务连续性风险
- 迁移期间服务不可用
- 迁移后系统性能下降
- 数据不一致导致业务流程中断

### 3.4 技术风险
- ETL脚本逻辑错误
- 数据库连接超时
- 网络传输中断
- 字符编码转换问题

## 四、测试维度

数据迁移测试应覆盖以下维度：

### 4.1 数据完整性测试
- 迁移前后数据量对比
- 主键唯一性校验
- 外键关联完整性校验
- 非空字段校验

### 4.2 数据准确性测试
- 字段值一对一比对
- 数据类型转换正确性
- 精度保持（如金额小数位）
- 特殊字符处理

### 4.3 数据一致性测试
- 关联表数据一致性
- 状态机流转一致性
- 时间顺序一致性
- 业务逻辑一致性

### 4.4 性能测试
- 迁移吞吐量测试
- 迁移对系统性能影响
- 大数据量批量处理能力
- 数据库负载监控

### 4.5 安全性测试
- 敏感数据脱敏处理
- 数据传输加密
- 权限迁移正确性
- 审计日志完整性

## 六、异常边界

### 6.1 数据异常场景
- 空值字段迁移处理
- 超长字段截断处理
- 非法字符转义处理
- 日期格式不兼容处理
- 编码不一致转换处理

### 6.2 网络异常场景
- 迁移过程中网络中断
- 数据库连接超时
- 批量传输部分失败

### 6.3 业务异常场景
- 迁移期间并发写入冲突
- 数据状态流转异常
- 关联数据部分缺失

### 6.4 系统异常场景
- 磁盘空间不足
- 内存溢出
- 数据库锁等待超时

## 七、自动化策略

### 7.1 数据比对自动化
```python
# 数据比对核心逻辑示例
def compare_migration(source_db, target_db, table_name, key_fields):
    source_count = source_db.query(f"SELECT COUNT(*) FROM {table_name}")
    target_count = target_db.query(f"SELECT COUNT(*) FROM {table_name}")
    assert source_count == target_count, "数据量不一致"

    # 抽样比对
    sample_records = source_db.query(f"SELECT * FROM {table_name} ORDER BY RAND() LIMIT 1000")
    for record in sample_records:
        target_record = target_db.query(f"SELECT * FROM {table_name} WHERE id = {record['id']}")
        assert record == target_record, f"数据不一致: {record['id']}"
```

### 7.2 自动化测试框架
- 数据比对脚本：源库与目标库数据一致性校验
- ETL流程监控：迁移任务状态实时监控
- 差异报告生成：自动生成差异明细报告
- 回归测试套件：迁移后业务功能验证

### 7.3 CI/CD集成
- 迁移脚本单元测试
- 数据格式校验集成测试
- 迁移后自动触发回归测试

## 八、数据环境

### 8.1 环境规划
| 环境类型 | 用途 | 数据量 | 备注 |
|---------|------|-------|------|
| 开发环境 | ETL脚本开发调试 | 小规模样本数据 | 快速迭代验证 |
| 测试环境 | 功能测试和性能测试 | 中等规模数据 | 模拟真实场景 |
| 预发环境 | 全量迁移预演 | 全量数据副本 | 正式迁移前演练 |
| 生产环境 | 正式迁移 | 全量真实数据 | 需停机窗口 |

### 8.2 数据准备策略
- 生产数据脱敏后导入测试环境
- 构造边界数据覆盖异常场景
- 准备标准比对数据集用于回归

### 8.3 数据隔离要求
- 迁移测试数据与生产数据物理隔离
- 测试账号与生产账号权限分离
- 敏感数据访问审计记录

## 九、监控回滚

### 9.1 迁移监控指标
- 实时迁移进度百分比
- 当前处理数据量/总数据量
- 迁移速率（条/秒）
- 错误率和错误类型分布
- 系统资源使用率（CPU、内存、磁盘、网络）

### 9.2 迁移日志记录
- 每条记录迁移状态
- 错误详情和堆栈信息
- 迁移开始时间、结束时间
- 数据转换前后值对比

### 9.3 回滚方案设计

#### 回滚触发条件
- 数据丢失率超过阈值（如0.1%）
- 数据一致性问题超过阈值
- 关键业务流程验证失败
- 系统性能严重下降

#### 回滚执行步骤
1. 停止增量同步任务
2. 恢复源系统写入权限
3. 清空目标系统迁移数据
4. 恢复源系统备份数据（如有变更）
5. 验证回滚后系统状态
6. 通知相关干系人

#### 回滚验证清单
- [ ] 源系统数据完整性
- [ ] 业务流程可正常执行
- [ ] 用户可正常访问
- [ ] 数据库状态正常
- [ ] 日志审计正常

### 9.4 应急预案
- 关键人员联系方式清单
- 数据库快速恢复脚本
- 服务降级方案
- 用户通知模板

## 十一、追问

面试官可能的追问及回答要点：

### Q1: 如何处理迁移过程中新增的数据？
**回答要点**：
- 增量同步机制设计
- 双写方案或binlog同步
- 数据版本标记和时间戳控制

### Q2: 500万数据量迁移需要多长时间？如何优化？
**回答要点**：
- 评估单条处理耗时和总耗时
- 批量处理优化（如每批5000条）
- 并行处理提升效率
- 数据库优化（索引、批量插入）

### Q3: 如何验证迁移数据的准确性？
**回答要点**：
- 全量比对（数据量小时）
- 抽样比对（大数据量时）
- 校验和比对（关键字段MD5）
- 业务规则校验

### Q4: 迁移失败如何回滚？
**回答要点**：
- 迁移前完整备份
- 增量数据回放日志
- 目标系统清空脚本
- 源系统恢复流程

### Q5: 如何评估迁移是否成功？
**回答要点**：
- 数据完整性指标（数量一致）
- 数据准确性指标（比对通过率）
- 业务功能指标（回归测试通过）
- 性能指标（响应时间、吞吐量）
