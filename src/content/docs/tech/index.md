## 模块定位

技术专题模块解决的是测试开发学习中的核心技术栈问题：

- **最小技术栈构建**：从 Python 基础到 pytest 框架，建立自动化测试的最小可行技能集
- **自动化工程能力**：掌握接口测试、Mock 技术、CI/CD 流水线，具备搭建自动化测试体系的能力
- **场景扩展能力**：从接口到 UI（Playwright）、从单机到容器化（Docker），覆盖更多测试场景
- **进阶质量能力**：集成质量门禁、覆盖率检查、多环境部署，构建完整的质量保障体系

这个模块是整个学习体系的"技术骨架"，将核心路径中的方法论转化为可落地的技术实践。

## 适合谁

### 初学者怎么用

如果你刚接触测试开发，建议按以下路径学习：

1. **先学 Python 基础**：掌握函数、列表、字典、异常处理，这是所有测试脚本的基石
2. **再学 pytest 框架**：学会组织测试用例、使用 fixture、参数化测试
3. **然后学接口测试**：理解 HTTP 协议，用 requests 库编写 API 测试

这一顺序让你从"能写代码"逐步进阶到"能写测试"，建立最小技术栈。

### 冲刺面试者怎么用

如果你正在准备面试，重点关注：

- **高频考点**：pytest fixture 作用域、HTTP 状态码含义、断言设计策略、Mock 使用场景
- **追问准备**：每个技术专题页面都提供了面试追问与回答骨架，帮助你应对深度追问
- **自我检测**：使用页面中的 selfTests 快速检验掌握程度

建议优先学习 interviewWeight 标记为 3 的页面：pytest、接口测试、CI/CD。

### 项目包装者怎么用

如果你需要快速产出项目成果：

- **最小可运行例子**：每个技术页面都提供了完整可运行的代码示例，可直接复制使用
- **项目落地章节**：按照"在项目中怎么落地"的结构搭建自己的测试工程
- **常见坑规避**：提前了解常见错误，避免踩坑浪费时间

建议从接口测试入手，配合 Mock 框架和 CI/CD，快速搭建一套完整的自动化测试体系。

### 进阶测试开发怎么用

如果你已有测试开发基础，追求更高水平：

- **深入理解原理**：不只是会用工具，更要理解 fixture 依赖注入、Mock 拦截机制、容器化隔离原理
- **扩展场景能力**：学习 Playwright UI 自动化、Docker 测试环境，覆盖更多测试类型
- **工程化思维**：关注 CI/CD 质量门禁、覆盖率阈值、多环境部署等系统性实践

建议阅读技术专题的"核心概念拆解"章节，理解底层原理，再结合场景模块进行综合实战。

## 推荐学习顺序

以下是技术专题模块的核心学习路径，建议按顺序学习：

1. [Python 测试开发基础](python) - 编程语言基础，函数、列表、字典、异常处理
2. [Pytest](pytest) - Python 生态最流行的测试框架，fixture、参数化、标记
3. [接口测试](api-testing) - HTTP 协议与 requests 库，断言设计与数据驱动
4. [Mock 框架](mock-framework) - 模拟外部依赖，隔离测试环境，提升稳定性
5. [CI/CD](ci-cd) - 持续集成与持续部署，自动化流水线，质量门禁
6. [Docker 测试](docker-testing) - 容器化测试环境，解决环境一致性问题
7. [Playwright](playwright) - 现代浏览器自动化工具，UI 测试场景扩展
8. [数据库测试](database-testing) - 数据库验证方法，SQL 断言与数据校验

**学习节奏建议**：

- 第 1-3 项为最小技术栈，建议集中 2-3 周完成
- 第 4-5 项为自动化工程能力，建议用 1-2 周掌握
- 第 6-8 项为场景扩展，可根据实际项目需要选择性学习

## 常见误区

### 误区一：只学工具不学原理

很多学习者只关注"怎么用 pytest"或"怎么写 requests"，却忽略了底层原理。面试时一旦被追问 fixture 依赖注入机制或 HTTP 协议细节，就无法回答。

**正确做法**：每个技术专题的"核心概念拆解"章节重点阅读，理解原理后再学用法。

### 误区二：跳过 Python 基础直接学框架

有些学习者急于求成，直接从 pytest 或接口测试开始，结果发现连基本的列表操作、异常处理都写不出来，严重影响学习效率。

**正确做法**：先扎实掌握 Python 基础，至少能独立编写简单的数据处理脚本，再进入测试框架学习。

### 误区三：只看不动手

只阅读文档不编写代码，以为自己理解了，实际动手时处处出错。测试开发是实践性很强的技能，不动手等于没学。

**正确做法**：每个技术页面都有"最小可运行例子"和"练习任务"，务必亲手运行并完成练习。

### 误区四：忽视工程化能力

很多学习者能写测试用例，但不知道如何组织测试工程、配置 CI/CD、搭建测试环境。这种能力只停留在"手工自动化"层面，无法胜任真正的测试开发岗位。

**正确做法**：学完基础层后，务必学习 CI/CD 和 Docker 测试，具备搭建测试基础设施的能力。

### 误区五：学完就忘不复盘

技术学习容易陷入"学完就忘"的循环。pytest 的 fixture 作用域、Mock 的使用场景等知识点，不定期复盘很容易遗忘。

**正确做法**：
- 定期回顾 selfTests 进行自检
- 将学到的技术应用到实际项目中
- 阅读面试追问章节，模拟回答加深记忆
